# AGENTS.md — CNAS (Criminal Network Analysis System)

Working brief for coding agents. It is enough to make changes without first
reading the whole tree. README.md is the human/judge-facing account of *why*;
this file is *how it fits together* and *what must not break*.

## What it is
An SIH 26189 prototype. Police records (FIRs, phones, accounts, vehicles…) are
modelled as one graph. Six detection "mechanisms" run over it and emit
**findings**, and each finding carries its own evidence. An officer reviews
them in a single-page console.

All data is synthetic, generated by `cnas/seed.py`, and must stay so: no real
people, numbers or cases.

- **Stack:** Python 3.11+, FastAPI, NetworkX, SQLite, scikit-learn. The
  frontend is plain HTML/CSS/JS with vendored Cytoscape.js.
- **Constraints:** no build step, no DB server, no network access at runtime.

## Commands
```bash
python -m venv .venv && .venv/Scripts/python -m pip install -r requirements-dev.txt   # Windows path
python run_pipeline.py        # rebuild data/ from seed; ends with 6 PASS/FAIL demo self-checks
python serve.py [--no-open] [--port 8077]      # console at http://127.0.0.1:8077
python -m pytest              # tests/ (each test rebuilds its own dataset in a tmp dir)
node --check web/app.js       # only JS check available (no bundler, no linter)
```

- **Resetting.** `run_pipeline.py` is the reset. It drops and rebuilds
  `data/graph.json`, `data/findings.json` and `data/cnas.sqlite`, which holds
  the audit log, the token vault, the model registry, **case notes** and
  **case milestones**. It must exit 0, with all six criteria PASS.
- **Environment on the dev machine.** It is Windows. If the global Python
  lacks the dependencies, use `.venv` (gitignored). Set `PYTHONIOENCODING=utf-8`
  when printing Devanagari or `→` to the console.

## Data flow
```
seed.py ──► run_pipeline.py ──► data/graph.json      (nodes, edges, merges, mo_profiles, transactions)
             │  ER (er.py)      data/findings.json   (list of Finding dicts)
             │  mechanisms.py   data/cnas.sqlite     (audit_log, token_vault, model_versions,
             │  seed.MILESTONES                        case_notes, case_milestones)
             ▼
api.py (FastAPI, holds graph + findings in memory, reloads on file mtime change)
             ▼
web/index.html + web/app.js + web/style.css   (served at / and /static)
```

## File map
| File | What lives there |
|---|---|
| `cnas/config.py` | **Every** constant. It covers paths, tiers/roles, ER thresholds, mechanism params, `EVENT_EDGE_TYPES`, `MODEL_VERSIONS`, `NODE_STYLE`, `PACK_LABELS`, `MECHANISM_FAMILIES`, `CASE_STATUSES`, `MILESTONE_KINDS`, `NOTE_COLORS` and the length limits. |
| `cnas/seed.py` | The hand-built dataset, with the six planted demo scenarios described in its docstring. `MILESTONES` holds the seeded investigative steps per case. `build()` and `write()` produce it. |
| `cnas/graph.py` | `GraphStore`, a NetworkX `MultiDiGraph` plus `raw`, the JSON it saves. Its methods: `visible(tiers)` (**all reads go through this**), `node`, `ego_network`, `path_between`, `timeline` (event-strip data), `centrality`, `canonical_map` (the SAME_AS closure), `cases_for`, `all_cases`, `search`, `apply_merge`, `unmerge`, `save`. |
| `cnas/er.py` | `Resolver` runs a deterministic pass on IMEI/account and similar, then a probabilistic three-band pass (auto_merge / human_review / reject). Merges are SAME_AS edges, and they are reversible. |
| `cnas/findings.py` | The `Finding` dataclass, the **Explainability Contract**: `__post_init__` refuses to build one without evidence, a confidence meaning and limitations. Also `save` and `load`. |
| `cnas/mechanisms.py` | `er_findings`, `structuring`, `structural`, `benford`, `cusum`, `mo_similarity`, `emergency_prior_hit`, and `run_all`. |
| `cnas/store.py` | SQLite. Covers `init(reset)`, the hash-chained `audit()`, `read_audit`, `verify_chain`, `audit_for_targets` (a safe projection), the token vault and the model registry. For the case file: `add_note`, `get_note`, `list_notes(case, tiers)`, `update_note`, `soft_delete_note`, `add_milestone`, `list_milestones(case, tiers)`, `content_digest`, and `now()` (UTC ms). |
| `cnas/casefile.py` | Assembles the case timeline on read and stores nothing: `build_timeline(...)`, `findings_on_network`, `sort_key` (normalises mixed timestamp formats), and `CATEGORIES`. |
| `cnas/auth.py` | `Principal(role)`. The role arrives in the `X-CNAS-Role` header, and `.tiers` / `.can_see(tier)` follow from it. The login is fake; tier enforcement is real. |
| `cnas/extract.py` | FIR document parsing: docx, pdf and txt become form fields, identifiers and MO features, each with source spans. Rule-based, no ML. |
| `cnas/intake.py` | `ingest(store, payload, actor)` adds a new FIR case to the live graph and validates everything before it mutates anything. |
| `cnas/report.py` | One block-based content model, rendered to `.docx` (python-docx) or Word-HTML. Covers `case_report`, `finding_report`, `queue_report`, `render`. |
| `cnas/api.py` | Every HTTP route (table below). Also the in-memory caches `_graph`, `_findings` and `_mtimes`. |
| `run_pipeline.py` | The staged pipeline plus the demo self-checks. |
| `serve.py` | Runs uvicorn on `cnas.api:app`. |
| `web/app.js` | The whole console. Global state lives in `S`, and `api()` adds the role header. Views: workspace (Cytoscape ego graph, events strip, details panel), review queue, evidence intake, emergency search, audit log, plus the case-notes and case-timeline `<dialog>`s. |
| `tests/` | `conftest.py` repoints `config` paths to `tmp_path`, runs `run_pipeline.main()` and resets the API caches. `test_notes.py`, `test_timeline.py`. |
| `samples/` | Synthetic FIR documents for the intake demo. `make_samples.py` regenerates them. |

## API
Every route takes the `X-CNAS-Role` header (`standard_officer` | `elevated_analyst` | `restricted_analyst`; the default is standard).

**Session, overview, graph**

| Route | Purpose |
|---|---|
| `GET /api/session` | Principal, roles, stats, `case_vocab` (statuses, milestone kinds, note colours) |
| `GET /api/overview` | Cases list and finding counts |
| `GET /api/ego-network/{id}?hops=` | Bounded subgraph, plus the `timeline` events strip |
| `GET /api/node/{id}` | One record, plus `cases` and `resolved_from` |
| `GET /api/chain?src=&dst=` | Shortest path (the cross-domain demo) |

**Findings and merges**

| Route | Purpose |
|---|---|
| `GET /api/findings[?status&family]` | Findings list |
| `GET /api/findings/{id}` | One finding |
| `POST /api/findings/{id}/confirm` and `/reject` | Decide a finding (reject needs `reason`) |
| `GET /api/merges/{id}` | One merge record |
| `POST /api/merges/{id}/unmerge` | Reverse a merge |

**Reports and intake**

| Route | Purpose |
|---|---|
| `GET /api/report/case/{id}` | Case report as `.docx` (`?format=doc` for Word-HTML) |
| `GET /api/report/finding/{id}` | Finding report |
| `GET /api/report/queue` | Review-queue report |
| `GET /api/intake/schema` | Intake form vocabulary |
| `POST /api/intake/parse` | Parse an uploaded FIR (multipart) |
| `POST /api/intake/fir` | File a new case |

**Case file**

| Route | Purpose |
|---|---|
| `GET /api/cases/{id}/notes` | Notes the caller can see (`mine` flag set) |
| `POST /api/cases/{id}/notes` | `{text, color?, tier?}` |
| `PATCH /api/cases/{id}/notes/{nid}` | `{text?, color?, tier?}`. Author role only (403 otherwise) |
| `DELETE /api/cases/{id}/notes/{nid}` | Soft delete. Author role only |
| `GET /api/cases/{id}/timeline?hops=` | `{case, status, status_label, entries[], counts, categories, span}` |
| `POST /api/cases/{id}/milestones` | `{kind, occurred_at (ISO, not future), title, detail?, tier?}` |
| `POST /api/cases/{id}/status` | `{status, reason, tier?}`. Updates the Case node, which everyone sees, and logs a `status_change` milestone carrying the reason, filed at `tier` (default: the author's highest) |

**Other**

| Route | Purpose |
|---|---|
| `GET /api/emergency-lookup?q=` | Direct identifier lookup (no scoring) |
| `GET /api/audit-log` | Audit entries plus chain verification |
| `GET /api/audit-log/verify` | Verify the hash chain |
| `GET /api/models` | Model registry |

**Timeline entry shape.** Each entry has `id`, `kind`, `category`, `at`,
`sort_key`, `time_basis` (`event`|`system`), `title`, `detail`, `actor`,
`tier`, `refs{node_id|finding_id|merge_id|milestone_id|note_id}` and
`ingested_time`.

`kind` values: `case_opened`, `evidence`, `network_event`, `merge`,
`finding_raised`, `finding_decision`, `milestone`, `status_change`, `note`.

## Invariants — do not break these
1. **Tier filtering happens server-side, in the query layer.** Every read takes
   the caller's `p.tiers`. For the graph that is `GraphStore.visible()`; for
   notes and milestones it is the `tiers` argument to the `store.list_*`
   functions. The UI never filters for access.
2. **Anything the caller can't see is a 404, never a 403.** Returning 403
   would disclose that the record exists. A 403 is only correct when the
   caller *can* see the thing but may not change it, such as another role's note.
3. **Every write is audited via `store.audit()`**, and the SHA-256 chain must
   stay intact (`verify_chain()`).
4. **Audit `detail` never carries free text written by officers.**
   `/api/audit-log` is **not** tier-filtered, so notes, milestone text and
   status reasons are logged as ids, tier, length and sha256 only. The
   finding-decision `reason` is the one long-standing exception.
5. **Every finding satisfies the Explainability Contract.** New mechanisms
   construct `Finding(...)` with evidence, `confidence_meaning` and
   `limitations`, and are versioned in `config.MODEL_VERSIONS`.
6. **Graph mutations update both `g.g` (NetworkX) and `g.raw` (what `save()`
   writes).** Then call `g.save()` and `api._mark_written("graph", …)`.
   Otherwise the next save or reload reverts the change. See `intake.ingest`
   and `api.set_status`.
7. **The API reloads on file modification time.** `api.graph()` and
   `api.findings()` reload when the files change on disk, so a pipeline rerun
   under a live server is picked up. After writing, call `_mark_written` so
   the server doesn't reload its own write.
8. **Standing relationships are not events.** Only `config.EVENT_EDGE_TYPES`
   go on the event strip or the timeline. `OWNS` and `LOCATED_AT` stay off.
9. **Findings are added by id and never overwritten.** Overwriting would
   silently revert an officer's decision.
10. **No person is ever scored.** There is no "risk" colour or number on
    people; node size is betweenness and the ring is a citation count.
11. **All dynamic HTML in `app.js` goes through `esc()`.**
12. **The data stays synthetic.**

## How to…
- **Add an API route.** Add it in `api.py`. Take `p: Principal = Depends(current)`,
  resolve records under `p.tiers` (use `_case_or_404` for anything scoped to a
  case), audit writes with safe `detail`, and add a test in `tests/`.
- **Add a detection mechanism.** Write a function in `mechanisms.py` that
  returns `list[Finding]`, add it to `run_all`, add its version to
  `config.MODEL_VERSIONS`, and render its `extra` panel in
  `app.js:mechanismExtras` and `report.py:_mechanism_blocks`.
- **Add a timeline source.** Add an `_entry(...)` block in
  `casefile.build_timeline`. Its inputs must already be tier-filtered, so pass
  them in from `api.case_timeline`, and give the entry a `CATEGORIES` key.
- **Add a UI view.** Add a `<main class="view" id="view-x">` plus a tab button
  in `index.html`, and extend `showView()` in `app.js`. Style it with the
  existing `:root` tokens in `style.css`. Nothing may float over the canvas;
  the modal `<dialog class="sheet">` is the only overlay pattern.
- **Change the seed data.** Rerun `run_pipeline.py` and confirm all six
  criteria still PASS. `tests/test_timeline.py` asserts facts about C-001,
  C-004, C-005 and C-007.

## Gotchas
- **`store.init()` runs when `cnas.api` is imported.** It creates any missing
  tables, which is safe on an old DB. Tests repoint `config` paths *before*
  importing `cnas.api` (see `conftest.py`).
- **Timestamps come in several formats:**
  - seeded event times are naive;
  - intake writes naive local time;
  - `store.now()` and ER `decided_at` are UTC with an offset;
  - `Case.opened` is date-only.

  Compare them only through `casefile.sort_key`.
- **Two id prefixes look alike.** Merge ids are `M-DET-…` / `M-PRO-…`;
  milestone ids are `MS-…`; note ids are `N-…`.
- **Intake reuses the next free case id,** which is why notes and milestones
  are wiped on reset.
- **Confirming or closing a case is only ever a status change,** so there is
  no `case_confirmed` or `case_closed` milestone kind. In the seed data, a
  case's `status` must match its last `status_change` in `seed.MILESTONES`;
  a test checks this.
- **Authorship is by role,** because the login *is* a role. A note is
  editable by the role that wrote it.
- **The toast has to move into an open `<dialog>`.** The top layer would hide
  it otherwise; `toast()` does this.
